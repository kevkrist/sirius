## Frozen CLI and schema v1

Target: `build/release/test/cpp/sirius_s4_experiment`. Invocation is `sirius_s4_experiment MODE --option value ...`. Modes: `identify`, `transport`, `builder`, `sql`. `--output PATH` is required and owns JSONL output; engine stdout/stderr are separate diagnostics. No append: each process receives its own output path. `--help` initializes no CUDA context.

Common options: `--run-id`, `--sample-id` (prefix), `--build-id`, `--process-cluster`, `--pair`, `--order`, `--seed`, `--warmups`, `--repetitions`, `--devices` (ordered comma-separated visible CUDA ordinals), `--root`, `--cap-bytes` (default 268435456), `--coverage` (default 0.9), `--profile`. Process cluster, pair, order, seed, warmups, and repetitions are integers. Sample IDs append `:warmup:i` or `:sample:i`; `repetition` is zero-based within its category. Python owns pairing, randomization, process clusters, workloads, and analysis.

- `identify`: no CUDA initialization; reports actual `compiled_schedule`, `linkage="static_sirius_core"`, absolute `executable_path`, `bloom_block_bytes`, `cuda_allocation_alignment`, and `duckdb_version`. The fixture is statically linked from the production objects; it does not claim to load the separately hashed shared library. Parent supplies matched extension/CLI validation.
- `transport`: `--pattern pair|all_pairs|root_inbound|root_outbound`, `--issuer destination_read|source_write`, `--bytes N`, and pair endpoints `--source`/`--destination`. One stream per edge; each edge has its own destination allocation. Real Sirius GPU spaces and their actual owning-pool grants are required. Unavailable grants are explicit skipped evidence, not a staged copy mislabeled direct.
- `builder`: `--bitmap-bytes N` (alias `--bytes`), `--keys 1|2`, `--rows N` (default 4096 per contributor), `--transport automatic|force_host|require_direct`. Root contributes last. B is exact, aligned whole-block geometry; production geometry derives C. `--contributors` optionally selects a subset of `--devices` and must include root. Empty contributions are supported with `--rows 0`. Cap refusal is explicit. No production SQL admission claim is made by this direct builder diagnostic.
- `sql`: `--database PATH` (or `:memory:`), `--query-file PATH`, optional `--prepare-file PATH`, `--config PATH`, `--query-id`, `--dataset`; normal SQL, one query per invocation. Native CPU execution supplies the oracle outside timed GPU queries. Preparation may create parquet views or native tables and pin them. Runtime snapshot deltas prove interception and distinguish publication skips. SQL configuration must name the requested devices.

Every sample has `schema_version=1`, `run_id`, `sample_id`, `build_id`, `mode`, `process_cluster`, `pair`, `order`, `seed`, `warmup`, `repetition`, `devices`, `root`, `compiled_schedule`, `linkage`, `profile`, `cap_bytes`, `coverage`, `status`, `skip_reason`, `oracle_outcome`, `oracle_passed`, and `gpu_intercepted`. Success is `status="ok"`, `oracle_outcome="passed"`. Other statuses include `skipped`, `unavailable`, and `error`; reasons are explicit. An unavailable oracle is null/`not_measured`, never passed.

Measurement fields: `actual_transport`, `transport_api`, `stream_owner`, `N`, `K`, `B`, `C`, `input_bitmap_bytes`, `ready_replica_bytes`, `published_bitmap_bytes`, `logical_edge_bytes`, `d2h_bytes`, `h2d_bytes`, `planned_logical_edge_bytes`, `planned_d2h_bytes`, `planned_h2d_bytes`, `scratch_requested_bytes`, `scratch_aligned_bytes`, `host_staging_physical_bytes`, `host_elapsed_ns`, `query_elapsed_ns`, `local_event_durations`, `physical_route`, `allocator_committed_peak_bytes`. Inapplicable or unavailable measurements are JSON null, with explicit availability strings where useful. Submitted bytes count successful enqueues and are distinct from planned bytes. Builder has zero published channel bytes because it returns ready filters without pushing channels.

SQL additionally reports exact counter deltas and the original `accumulation_publication_latency_ns` separately from preparation-through-completion time. A zero-publication query remains an end-to-end parity observation, with an explicit `publication_skip_reason`; it cannot become a zero-latency publication win. `gpu_intercepted` requires one successful rebind/execution and no plan/runtime fallback or read-view mismatch. Result digest is supplementary; full result comparison determines the oracle.

`submitted_bytes_complete` distinguishes a complete submission account from partial or failed work. Transport `per_gpu_tx_bytes` and `per_gpu_rx_bytes` align with `devices` and count logical submitted bytes; they are not measured bus traffic. `timing_scope` is `copy_submission_through_completion` for transport, `publication_prepare_through_completion` for builder, and `normal_sql_query` for SQL. SQL `publication_timing_scope="sum_all_finish_attempts"` describes the aggregate production counter; it is reported only as a duration when at least one publication completed. SQL root/K/B/C are null because native query snapshots do not expose per-publication geometry. Process failures can append a final error record with null repetition and exit nonzero.

SQL opts into existing internal test options using a scoped `SIRIUS_ENABLE_TEST_OPTIONS=1` before database creation, matching the unit-test setup. `add_sirius_option` gates internal cap/enable settings on this variable; coverage is already public. This gate does not select the publication schedule. After preparation and existing SET statements, the fixture verifies cap, coverage, and both dynamic-filter enable flags through `duckdb::session_operator_params`, which owns connection-local overrides. Startup `SiriusContext` configuration alone would not verify SET effects. SQL records expose `internal_test_options_enabled`, `profile_verified`, `enable_dynamic_filter`, and `enable_dynamic_filter_multi_partition` as true after this verification. Poincare retains existing preparation SETs and records the gate in runner provenance.

## Correctness and integration

Transport verifies every destination byte and checks that all source bytes remain unchanged after completion. The builder calls production `enqueue_add`/`finish_for_experiment`; `inspect_partial` supplies independent host snapshots before publication. The fixture ORs every snapshot byte, compares every returned replica, and probes every inserted key on every replica for false negatives. Independent N/K/B/C accounting checks cover bitmap bytes, submitted versus planned legs, aligned device scratch, and physical fixed-block HOST staging. Verification and input generation are outside publication timing. Failed stream retirement terminates the process before dependent pool storage can be released.

The SQL oracle reuses `sirius::test::collect_rows`, tags NULL separately from the string "NULL", sorts rows, and compares the complete result and types exactly. Floating-point SQL results currently receive exact comparison too; any tolerance change requires observed evidence and coordination with reviewer Rawls. No CPU-oracle change accompanied the internal-option fix.

Parent build registration needs the three new `.cpp` files, `src/sirius_extension_entry.cpp`, and existing `test/cpp/utils/sirius_extension_loader.cpp`, with the standard native `sirius_core`/DuckDB dependencies and include directories. No other test utility source, `sirius_test_env.cpp`, Catch runner, or Catch link is required. Existing result collection is header-only; standalone context checks do not invoke Catch assertions.
